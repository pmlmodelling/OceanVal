    Validate an ocean model

      Tell OceanVal about your simulation files

      Use 2 for output filed as sim/YYYY/MM/*.nc, 1 for sim/YYYY/*.nc, and 0 for a single directory.

      Once you have told OceanVal the names of model variables it will be able to identify which files contain them, and it will use the files with the highest temporal resolution. However, sometimes you have files that could trip up OceanVal's file identifier. For example, you might have files covering the entire simulation, but others covering a spatial subregion. In this case, OceanVal needs to be told some further details to dig down.

      This is created to produce a fully reproducible version of this validation that can be run from the command line. You will not need to run this, and the file is saved for completeness.

      As well as OceanVal's built-in datasets, you can validate against observations of your own, point data (csv files) or gridded data (netCDF). Do you have any to add?

      A model and its observations can report the same quantity in different units, for example nutrients in mmol/m3 against µmol/kg, and OceanVal compares the values as they are. So OceanVal has compared the units of each matchup. Where it thinks they are the same, it has left the boxes empty, and where it thinks they differ, it has suggested a conversion: the observations become observations × multiply by + add before they are compared with the model.

      The model's units are read from its netCDF files, and the observations' from OceanVal's recipes (as on the recipes page of the documentation) or from the netCDF file you supplied. OceanVal can get this wrong, so check every row, not only the conversions it suggests, which are in red and bold, and fill in any it could not work out. Leave the boxes empty where you agree that no conversion is needed. The units always have to be confirmed, at the bottom of the page, before the matchup starts.
